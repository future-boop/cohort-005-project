# Notification providers for Cadence

Research for [#11](https://github.com/future-boop/cohort-005-project/issues/11) (child of map [#10](https://github.com/future-boop/cohort-005-project/issues/10)). Researched 2026-11-10 against vendor docs and pricing pages. npm versions were checked with `npm view` on the same date.

Bar from the map: a usable free tier and a JS/Node SDK. We build our own Notification Feed UI on the provider's API, so prebuilt components are ignored. Pricing at scale and compliance are out of scope.

Facts marked **(unverified)** could not be confirmed from a first-party page.

## Web push platform facts (independent of provider)

- iOS/iPadOS web push needs **iOS 16.4+** and the site **added to the Home Screen** as a web app. The manifest's `display` must be `standalone` or `fullscreen`. Permission must be requested from a user gesture. It uses standard Push API, Notifications API and Service Workers, and does not need an Apple Developer account. Push is not available in a normal Safari tab on iOS. [WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
- For Cadence this means a web app manifest, a root-scoped service worker, HTTPS (localhost is fine in dev), and a "turn on notifications" button.
- EU: Apple planned to drop Home Screen web apps in the EU in iOS 17.4, then reversed before release ([Apple dev forums](https://developer.apple.com/forums/thread/748026)). A MagicBell blog post still says EU PWA push doesn't work on 17.4+. Current status is **unverified**, and it doesn't matter for a throwaway project.

## Recommendation

Shortlist **Knock** first and **Novu** second. Drop MagicBell and SuprSend unless web push becomes the deciding factor.

- **Knock** fits the core channel, the Notification Feed, best. Its client has every feed operation (seen/read/archive and the inverses), unread and unseen counts in feed metadata, and a one-call WebSocket subscription. 10k messages/mo is plenty. Preferences are fully included on Free. Recipients are our user ids with inline identify on trigger. Its built-in testing email provider means email can be tried without signing up for Resend/SendGrid. The cost is web push: it only goes through FCM, so it needs a Firebase project and Firebase's service worker.
- **Novu** is a close alternative with an equally complete headless client (`@novu/js`), realtime and preferences. It has the same FCM-based web push story. Its demo email only reaches the Novu account owner, and its activity log keeps 24h on Free.
- **Courier** clears the bar, but it is weaker on web push docs and its test email only reaches the signup address.
- **MagicBell** has the cleanest standards-based web push (our VAPID keys, no Firebase). Its free tier is only 1,000 deliveries/mo counted per channel, and email needs our own provider.
- **SuprSend** has native web push with managed VAPID. However, user preferences are not on the Free plan, which the map's "Notification preferences" item needs, and email needs our own provider.

This is input for #13, not the decision.

## Implications for other tickets

- **#14 channels:**
  - With Knock, Novu or Courier, web push means adding a Firebase project and FCM. Only MagicBell and SuprSend speak standard Web Push natively.
  - Any provider needs a manifest and a root service worker. iPhone users must install Cadence to the Home Screen first.
  - Real email to arbitrary users needs our own email provider on every option. The built-in test senders of Novu and Courier only reach the account owner, and Knock's testing provider's limits are unverified.
- **#15 feed UI:**
  - All five separate *seen* from *read*. Knock and Novu expose both unread and unseen counts. MagicBell exposes unread only, and Courier exposes unread only.
  - Realtime events from Knock carry only counts, and those from Courier carry no count at all. On both, the UI refetches the list on event.
- **#12 first batch:** Free-tier volume is not a constraint at ~5–8 Notification types, except on MagicBell, where multi-channel sends count once per channel against 1,000/mo.
- **Triggering / DevUI:**
  - Every provider keys recipients by our user id, which fits the DevUI user switcher.
  - Every provider needs a server-minted per-user token (Knock RS256, Courier issue-token, MagicBell HS256, Novu HMAC), so a loader must issue it for the current DevUI user.
